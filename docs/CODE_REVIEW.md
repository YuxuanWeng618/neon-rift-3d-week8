# 代码复核记录

日期：2026-10-11。复核者：Codex。范围：PR #1 内成员A刷怪功能、成员B生存模式、主场景、运行脚本及测试。这是工具辅助的技术复核，不是队友 `dy992` 的人工批准。

## 发现与处理

启动脚本未找到 PATH 中的 Godot 时会退回开发者的 `E:` 盘固定路径，无法作为队友电脑的默认启动方式。已删除该路径，改为显式 `-GodotPath`、`GODOT_DOTNET_PATH` 或 PATH；缺少引擎、.NET SDK或误用普通版 Godot时给出明确错误。新增 `-VerifyOnly` 和 `-IncludeWindowTests`，让队友能执行同一套验证。缺失引擎和无效参数组合的错误分支已实际检查。

## 游戏与设计复核

| 检查范围 | 结论与依据 |
| --- | --- |
| 课程选项 | 只实现 Change Request 01：60秒存活；没有把其余三个选项作为额外要求 |
| 胜负 | 击杀只计分；管理器统一处理到期胜利和提前死亡；结束事件只能从Running生效一次 |
| 时钟与阶段 | Game3D每次物理更新只调用一次生成器；计时与难度读取同一个ElapsedSeconds，HUD不推进时钟 |
| 边界规则 | 管理器优先级100，在战斗更新后检查；同一物理更新内致死和到期按失败处理，已记录并测试 |
| 结束与重启 | 停止生成器和实体更新；HUD保持可点击；重启延迟执行、清理实体、重置玩家/得分/阶段；防止重复点击和按住射击穿透新回合 |
| 成员A接口 | 保留原有生成器提交与事件接口；阶段、安全位置、20上限及空位补充通过回归 |
| 职责 | 玩家处理输入和生命值；生成器处理刷怪；管理器处理结果；HUD处理显示；共享视觉参数不混入战斗规则 |
| 场景与资源 | 正式入口是Main3D.tscn；测试/录制场景独立；文档图片不作为游戏资源导入 |
| 清理与订阅 | HUD退出时解绑；管理器退出时解绑RoundStarted；旧实体先脱离场景树再释放，20次重启检查通过 |
| 运行可移植性 | 去除本机引擎固定路径；提供第二台电脑的环境、克隆、验证与人工记录步骤 |

保留的设计取舍：当前仅有一个生存模式，采用生成器已存在的时间源，避免增加第二个计时器。未来若加入多模式或独立暂停刷怪，应考虑把时钟抽离；本次不预先增加未使用的模式框架。玩家HP100、速度7保留，四组脚本试跑不足以替代人工难度评价。
