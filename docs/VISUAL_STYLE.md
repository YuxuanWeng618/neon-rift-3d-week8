# Neon Rift 3D：明亮街机视觉规范

日期：2026-10-11。适用范围：WENG YUXUAN 负责的玩家显示、HUD、主场景视觉、胜负与重启界面。

本规范记录用户选择继续采用的明亮街机版本。后续制作直接使用 Godot 原生场景和 C#，不使用任何 skills。用户已授权推送，成果通过功能分支交付，主分支合并经过PR审查。

## 1 画面目标

玩家首先看清自己的蓝色角色、红色追击敌人和紫色远程敌人，再快速读取剩余时间和生命值。浅色背景与淡绿色棋盘地面形成场地，黄色边缘标出竞技场范围。角色使用原项目的简单几何体，通过颜色、朝向和阴影区分。

保留目前通过审阅的基本布局。常驻信息分散在屏幕边缘，中间区域用于战斗；结算使用全屏浅色遮罩、醒目结果与一个重启按钮。

## 2 颜色与用途

| 名称 | 数值 | 使用位置 |
| --- | --- | --- |
| Paper | `#F1F2E9` | 屏幕背景、重启按钮文字、结算遮罩底色 |
| Ink | `#171D25` | 正常倒计时、主要文字、重启按钮 |
| Muted | `#69716F` | 说明文字、结果数据 |
| Accent | `#2254DE` | 生命条、时间进度、胜利结果、按钮悬停 |
| Danger | `#D93E24` | 最后10秒、低生命值、失败结果 |
| Track | `#D2D7CC` | 生命条与时间条的未填充部分 |
| Floor base | `#8D9C82` | 原地板材质 |
| Tile A / B | `#B0C2A4` / `#9EB092` | 两种棋盘地砖 |
| Wall | `#ADBCA1` | 原有围墙 |
| Arena edge | `#E6ED34` | 场地四周边缘 |
| Player | `#1440E6` | 蓝色玩家几何体；材质RGB为`0.08, 0.25, 0.9` |
| Aim marker | `#0F1F40` | 玩家前方的深色朝向标记 |

3D材质受到环境与方向光影响，截图像素不会全部等于材质的十六进制值。敌人和弹丸继续复用成员A及原项目的场景。

颜色集中在 `Scripts3D/SurvivalVisualStyle.cs`，HUD与竞技场从这里读取。玩家场景的基础材质同时保留蓝色；运行时也读取同一组视觉参数，防止后续场景预览与实际游戏各用一套颜色。

## 4 布局

| 区域 | 内容 | 基准位置 |
| --- | --- | --- |
| 左上 | NEON RIFT、SURVIVAL / 60 SECONDS | 左34，上28 |
| 顶部中央 | 整数倒计时、说明、细时间条 | 水平居中，区域宽180 |
| 右上 | ELIMINATIONS、击杀/得分 | 右34，上32 |
| 左下 | HEALTH、生命条、当前/最大HP | 左34，下26，生命条宽280、高16 |
| 底部中央 | 移动、瞄准、射击提示 | 水平居中，下23 |
| 右下 | 当前难度阶段、刷怪间隔 | 右34，下27 |
| 结算 | 结果、存活时间、击杀、得分、PLAY AGAIN | 中央；按钮宽340、高60 |

Godot使用锚点和边距定位，采用canvas_items与expand宽高比设置。4:3窗口扩展可视区域，实际输出为960×720；锚点继续贴合窗口边缘。普通HUD控件允许鼠标输入穿过；结算遮罩与重启按钮接收输入。UI只显示状态与发出重启请求。

## 5 游戏状态显示

| 条件 | 表现 | 恢复条件 |
| --- | --- | --- |
| 正常进行 | 黑色倒计时、蓝色生命条 | 随事件持续更新 |
| 剩余时间≤10秒 | 倒计时与说明为Danger，说明为FINAL SECONDS | 重启或进入新一局 |
| 当前HP≤最大HP的30% | 生命数字和生命条为Danger，说明为LOW HEALTH | 重置生命值后恢复 |
| 胜利 | 蓝色SURVIVED、最终数据、重启按钮 | 点击重启 |
| 失败 | 红色SIGNAL LOST、死亡时数据、重启按钮 | 点击重启 |
| 重启 | 满血、60秒、正常文字颜色，结算隐藏 | 开始下一局 |

低血量与最后10秒提示同时满足时同时显示。提示使用颜色和明确文字，不增加闪烁。结算遮罩采用Paper、透明度0.94；战斗数据冻结，界面继续响应。

## 6 竞技场

- 保留原场地20×14和全部碰撞形状。
- 使用10×7棋盘地砖，地砖仅用于显示。
- 四周围墙顶部增加黄色边缘。
- 保留原透视相机位置，视角为60度。
- 环境光能量0.4，方向光能量0.45，开启角色阴影。
- 玩家朝向标记位于角色前方，旋转跟随玩家瞄准。

视觉脚本不控制刷怪、伤害、生命值或胜负。

## 7 制作与验收顺序

1. 固化颜色、字号、提示阈值与光照参数。
2. 补齐最后10秒、低HP、二者同时出现和重启恢复画面。
3. 检查1280×720、960×540及不同宽高比的HUD、瞄准与按钮。
4. 复查计时、胜负、停止、重启和成员A接口。
5. 记录不同控制策略下的完整试玩结果，保留玩家参数决策依据。
6. 保存真实游戏演示与测试日志，更新T01–T16验收记录。

正式版本继续使用60秒、100最大HP、速度7、射速5。仅在测试场景比较其他参数；最终调整以试玩记录为依据。功能分支已合入main，技术复核与本机复验已完成；人工试玩、双机验收和队友实际审查结论仍待记录。
